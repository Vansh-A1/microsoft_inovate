## Executed controls

PostgreSQL integration tests exercise forced tenant/entity RLS, composite scope links, cross-tenant evidence/audit/review denial, unauthorized policy/master activation, forged actors/roles, self-approval, waiver authority, stale approvals/review writes, idempotency and audit rollback. Release tests add future policy version retention and scope checks, permission revocation before cached administration replies, narrow finance access and redacted request telemetry. Domain monetary values remain Decimal/decimal strings; original rules and historical policies/evaluations are retained.

Twelve pure release boundary cases validate generated RSA-signed Entra tokens, exact issuer/audience/tenant/client/membership, invalid signature/claims and key-service outage, plus required database TLS and provider HTTPS. Mocked Blob contracts verify immutable private keys, cross-scope denial, SHA-256 verification, tampering, remote missing/outage even with a warm cache, and fail-closed enterprise storage settings. They are not live Entra/managed-identity/private-network tests. Azure Blob endpoint support is currently public Azure only.

Document coverage includes MIME/content mismatch, size/page/pixel limits, corrupt/encrypted quarantine, page/source access, bounded subprocess parsing, unsupported/uncertain input, provider errors/disagreement, original preservation and no arbitrary instruction execution. A real malware engine is NOT_CONFIGURED; required scanning prevents progression. Spreadsheet formulas/macros are never executed; safe CSV export remains tested. No permanent public invoice URL is issued.

Enterprise navigation follows server membership; policy-only actors cannot open finance routes, and ordinary finance reviewers cannot read infrastructure health. Browser tests also verify cross-origin mutation denial, source/role business forms, and development-free presentation against the real document backend. Hosted tokens/private egress/TLS must still be verified before real data.

## Dependency, secret and source checks

Application dependencies are locked; added enterprise boundaries use PyJWT 2.15.1, azure-storage-blob 12.31.0 and azure-identity 1.26.0. `pip check`, pinned `pip-audit` on the Python lock and npm audit were actually run. Scan results are time-bound observations, not a guarantee against future vulnerabilities. Tool dependencies are isolated under ignored runtime.

Gitleaks 8.30.1 is downloaded from its official release with verified archive SHA-256. A tracked/pending-source snapshot excludes ignored runtime secrets/artifacts. Configured scan finds zero findings; a randomly generated synthetic credential-format probe is detected and redacted. The only allowlist is an AND match on one synthetic README fixture-validation prose line, reviewed after the initial false-positive finding; it does not disable a credential detector. A separate bounded source/path scan checks known credential patterns and forbidden private artifacts. These do not replace an institutional secret-management review.

Original team-pack inputs, working specification, fixture manifests and historical phase exit reviews are checked separately. Uploads, model artifacts, tokens, private settings, backups, export files, screenshots and runtime reports remain ignored. Required business audit persists atomically. Telemetry deliberately omits raw URL/query/token/body/content/exception text and uses only a matched route template and correlation.

## Deployment and remaining risks

Bicep compiles locally and specifies internal CPU ingress, private database/storage/registry/Key Vault, separate managed identities and named secret scopes. Compiled definitions cannot prove Azure policy acceptance, DNS/TLS, identity exchange, egress, RBAC propagation or recovery. CPU image builds/OS-package scanning and hosted CI have not run on this blocked Docker host. Deployment requires protected approval, reviewed commit/parameter digest, immutable images and an explicit migration step.

Remote Blob health reports CONFIGURED_UNVERIFIED rather than mistaking a writable cache for remote availability. Scoped local reconciliation does not perform cloud-wide object enumeration. Dedicated cloud alerts/retention/access reviews need approved policy and live validation. No actual enterprise VLM, representative classifier, SHAP, payment execution, confidential dataset or production pilot is claimed.
